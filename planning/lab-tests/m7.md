# Lab-test evidence — M7: Multi-Agent Incident Crew

**Machine:** Apple Silicon (arm64), 16 GB · Rancher Desktop · native Ollama 0.40.7 (MLX runner) · ChromaDB 1.5.9
**Date:** 2026-10-21
**Crew:** `labs/m7/crew/` — four declarative profiles (Triage → Investigator → Fixer → Reviewer),
one shared `qwen3.5:2b`, `crew.py` glue. Reuses the Acme runbooks (agentic RAG) from M6.

## What changed in this pass

1. **Chroma v2.** The server image moved from `chroma:0.5.20` to `1.5.9`. Chroma 1.x serves only `/api/v2`.
   With the new image and the old `crew.py`, 3 of 5 checks failed (RED, below). `crew.py` now builds its URLs
   with `chroma_v2_base()`, the same helper pattern as M6's `agent.py`. `"think": False` on the generate call is kept.
2. **The Reviewer now receives the runbook passage.** On `qwen3.5:2b` the Reviewer REJECTED the correct
   checkout fix on 6 of 6 runs, because it was asked whether the command "matches the runbook" without
   being shown the runbook. Passing the retrieved passage to the Reviewer fixed it (5 of 5 APPROVED, then
   the full lab flow below). The model was **not** bumped.
3. **`qwen3:4b` is not a drop-in fallback.** It was tried first. The build we have ignores `think: false`
   and prints its reasoning inline, so the YES/NO relevance gate read NO and the crew escalated every
   incident. The lab's troubleshooting callout now says so.
