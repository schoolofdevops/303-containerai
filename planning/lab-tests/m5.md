Cause: `rag_roundtrip.py` drives Chroma over raw HTTP and used the `/api/v1` routes that Chroma 1.x removed:

```
urllib.error.HTTPError: HTTP Error 405: Method Not Allowed
```

Honest note: the old 0.5.20 *client* still answered `heartbeat()` and `list_collections()` (returned `[]`) against the
1.5.9 server, so the brief's predicted "handshake failure" did not reproduce for those two calls. The retired-route
failure is the reproducible break. The pin therefore rests on the major-version/API-route change, not on a handshake error.

Second finding: Chroma 1.x stores data under `/data`, not `/chroma/chroma`. A volume left at the old path would stay empty.
`compose.yaml` now mounts `chroma_data:/data`; persistence verified below.
