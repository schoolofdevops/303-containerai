## Check-strength proof (client-answers-via-v1)

The check now requires `reasoning_effort="none"` in client.py, a non-empty reply, and a run time under 45 s. Switch-off removed from client.py (image rebuilt):

- Timing/reply leg alone, run by hand as `sh -c` of the check's command with the guard removed: exit=1 after 48 s wall. That includes about 3 s of compose overhead, so the client call itself took about 45 s, right at the limit.
- Three measured runs of the client with the switch-off removed took 48 s (the check's timing leg, including about 3 s compose overhead), 59 s (a discarded perl-alarm experiment) and 1 m 47 s (a standalone run). No measured run came in under 45 s, but thinking time varies run to run, so a faster run could in principle slip under; the static `reasoning_effort` grep in the check covers that case.
- Full check: FAIL (5/6).
- Restored client.py: PASS (6/6).

A non-empty-reply assertion alone was not enough: with thinking on, this short prompt still returned content, only after 59 to 107 s.
